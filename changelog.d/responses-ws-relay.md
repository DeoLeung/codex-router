- **Incremental turns stay incremental end to end.** When Codex is connected over the router's WebSocket edge and the frame's model belongs to a websocket-transport provider, the edge relays the protocol through an authenticated forwarder hop instead of translating it into the loopback HTTP POST: a `previous_response_id` frame crosses every hop as-is, so only the new input is sent and the provider holds the conversation state. Continuation recovery keeps its documented contract — a provider 409 or a lost baseline makes Codex retry the full request — turn state is re-injected per frame, and usage/timing lines keep flowing via the relay path.
