- **Relay incremental Responses turns without bypassing the canonical pipeline.** Rebuilt per the relay review: every relayed `response.create` passes through the forwarder's `normalizeBody` (model id translation, endpoint policy, effort ladders, tool repair, image handling, identity stripping) before the provider wire -- `previous_response_id` is the one field normalization does not own, so the incremental contract survives. Continuation affinity is honored with a sticky connection: a hop holds one pooled connection for its lifetime, the connection that produced a response id is the connection asked to continue it, a dead connection drops the lease, and the provider's 409 drives the documented full-request recovery. An unopenable hop falls back to the loopback translation per frame.
